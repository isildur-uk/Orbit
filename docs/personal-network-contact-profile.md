# Contact Profile

The Personal Network surface will double as an address book. Selecting a
person opens a living Contact Profile, built from the same graph and evidence
used by the orbit view.

The existing ORBIT subject-profile work is useful as a structural reference:
ordered sections, source-backed fields, linked records, timeline material and
exportable profiles. Its law-enforcement vocabulary is deliberately excluded.

## Profile contract

### Header

- Name and preferred name
- Photo, when explicitly provided
- Preferred contact methods
- Current role and organisation
- Location, if known
- Last reviewed

### Relationship

- How we know each other
- Relationship category
- Strength and trajectory
- Last interaction
- Typical interaction cadence
- Shared contacts
- Network position: bridge, cluster, centrality and relevant paths

### Context

- Current work and projects
- Interests
- Expertise
- Current needs
- Offers and ways they can help
- Personal context entered or confirmed by the user

### Activity

- Interaction timeline
- Meetings and messages
- Introductions
- Commitments and promises
- Opportunities involving this person
- Dormant-relationship signals

### Evidence

Every field or statement should carry:

- source type: private, public, user-entered, calculated or AI inference
- source reference
- observed date
- valid-from and valid-until where relevant
- confidence or provenance grade where relevant
- superseded status when newer information replaces it

## Product rules

The profile is an address book with analytical depth, not a surveillance
dossier. The system should help the user remember, understand and act on their
relationships. It must not infer sensitive personal attributes merely because
they appear in a social export, and it must never silently turn a social-media
signal into a fact.

Social handles belong under contact methods / digital presence. A message or
meeting can support relationship history; a like, follow or view is only a weak
signal unless the user confirms its meaning.
